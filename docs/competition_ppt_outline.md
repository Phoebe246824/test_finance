## P2 · 行业背景与痛点 〔评分 2.1，10 分〕

- 场景：银行零售业务的反欺诈、反洗钱（AML）、贷款欺诈、可疑交易复核。
- 三大痛点（配图标）：
  1. **数据分散**：交易流水、账户关系、设备指纹、客户资料、投诉线索分散在不同系统，人工串联慢。
  2. **组合风险难发现**：传统规则易漏掉「多笔历史低风险 + 当前单笔异常」的累积型风险（如分拆转账/结构化洗钱）。
  3. **合规与隐私约束**：客户身份、流水、贷前材料高度敏感，**不允许上传公有云**做大模型分析。
- 数据支撑（可选）：「引用一条监管/行业报告数据，如 AML 误报率、人工研判平均耗时 XX 分钟/单」。

## P3 · 问题定义、目标用户与端侧必要性 〔评分 2.1 + 隐私铺垫〕

- **目标用户**：反欺诈分析员、反洗钱调查员、贷前风控专员、网点/远程银行运营。
- **要解决的具体问题**：把"一条可疑事件 → 历史线索串联 → 风险定级 → 调查摘要"的链路自动化，分析员只做最终复核。
- **为什么必须端侧/本地**（四点，直接对应评分加分项）：
  - 隐私合规：敏感金融数据不出银行内网；
  - 弱网/离线：网点专网、隔离环境可运行；
  - 低延迟处置：本地推理省去往返；
  - 数据主权：本地知识库可持续沉淀，不依赖外部服务可用性。

## P5 · 核心创新点 〔评分 1.1，15 分〕

四个区分度卖点（每点一句话 + 一张小图）：

1. **暂存—回捞机制**：未命中事件不丢弃，写入 Milvus 形成"客户正常行为基线"；高风险事件触发时按同客户/同账户/语义相关回捞历史，**专治累积型/分拆型风险**。
2. **多维加权风险评分**：7 个金融维度（客户身份 0.15 / 交易行为 0.25 / 交易对手 0.20 / 金额速度 0.15 / 设备地理 0.10 / 历史上下文 0.10 / 合规信号 0.05），可解释、可调权。
3. **时序知识图谱研判**：Graphiti+Neo4j 把离散事件织成人—账户—设备关系网，风险评估**有可追溯上下文**而非黑盒打分。
4. **二次研判闭环**：补图后再检索、再评分，输出调查摘要 + 证据点 + 处置建议，逼近真实分析员工作流。

## P6 · 智能体设计与多步任务 〔评分 1.1 + 1.3〕

## P7 · AMD 硬件利用：异构分工与统一内存 〔评分 1.2，10 分〕

- **硬件分工图**（CPU + GPU + NPU + 统一内存 96G）：
  - **GPU（Radeon 8060S，ROCm/llama.cpp 后端）**：承载核心 LLM 推理、Embedding、向量检索等高吞吐任务 ← *核心推理任务在此执行，满足"必须使用 GPU"硬性要求*。
  - **NPU（Ryzen AI）**：低功耗常驻轻量任务（关键词/设备异常预筛、监控逻辑）——如本届未落地则明确标注为规划方向，不虚报。
  - **CPU**：CrewAI 调度、Redis/Milvus/Neo4j 访问、规则过滤、JSON 解析、日志。
  - **统一内存（UMA）**：LLM + Embedding + 图谱 + 向量库同机并发，省去多模型显存瓶颈。
- **硬件使用证据**（关键，截图）：推理时 `rocm-smi` 的 GPU 利用率/显存占用、llama.cpp 的 `--n-gpu-layers` offload 日志。
- 系统状态页 `/system` 实时展示硬件画像（`/api/system/hardware`）。

## P8 · 本地化部署与量化策略 〔评分 3.2，7 分〕

- 模型本地化路径：llama.cpp（ROCm/HIP 或 Vulkan 后端）运行**量化模型**。
- 量化方案：「LLM：Qwen2.5-14B-Instruct **INT4(Q4_K_M)** / Embedding：bge-m3 / Rerank：bge-reranker-v2-m3」。
- 为何选该量化档：在 96G 统一内存内兼顾精度与吞吐，单机可并发 LLM+Embedding+图谱。
- 一句能效主张：*"用量化把大模型塞进端侧，换来可接受的精度损失与显著的本地吞吐/能效收益。"*
