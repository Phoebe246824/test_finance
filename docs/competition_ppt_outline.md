## P3 · 行业背景与痛点 〔评分 2.1，10 分〕

- 一句核心论点：**银行风控的真痛点是"组合风险"与"隐私约束"，而非单条规则。**
- 场景：反欺诈、反洗钱（AML）、贷款欺诈、可疑交易复核。
- 三大痛点（图标式）：
  1. **数据分散**：流水/账户/设备/资料/投诉分散在不同系统，人工串联慢。
  2. **组合风险难发现**：传统规则漏掉「多笔历史低风险 + 当前单笔异常」（分拆转账/结构化洗钱）。
  3. **隐私合规约束**：敏感金融数据**不允许上公有云**做大模型分析。
- 可选数据：「引用一条监管/行业报告数据，如 AML 误报率、人工研判平均耗时 XX 分钟/单」。

## P6 · 核心创新点 〔评分 1.1，15 分〕

> 一页一信息原则：若投影偏挤，**拆成 2 页**或用 2×2 卡片。

- 一句核心论点：**四个"区分度"设计，专治组合型金融风险。**
  1. **暂存—回捞机制**：未命中事件不丢弃，进 Milvus 形成行为基线；高风险时按同客户/同账户/语义回捞历史。
  2. **多维加权风险评分**：7 维（客户身份/交易行为/交易对手/金额速度/设备地理/历史上下文/合规信号），可解释、可调权。
  3. **时序知识图谱研判**：Graphiti+Neo4j 织成人—账户—设备关系网，打分有可追溯上下文。
  4. **二次研判闭环**：补图后再检索再评分，输出摘要+证据点+处置建议。

## P8 · AMD 硬件利用：异构分工与统一内存 〔评分 1.2，10 分〕

- 一句核心论点：**核心推理跑在 Radeon GPU 上，统一内存让多负载同机并发。**
- **硬件分工图**〔素材 #12，需新建〕：
  - **GPU（Radeon 8060S，ROCm/llama.cpp）**：核心 LLM 推理、Embedding、向量检索 ← *满足"必须使用 GPU"硬性要求*。
  - **NPU（Ryzen AI）**：低功耗常驻轻量预筛——**未落地则标"规划方向"，不虚报**。
  - **CPU**：CrewAI 调度、DB 访问、规则过滤、日志。
  - **统一内存 96G**：LLM+Embedding+图谱+向量库同机并发，免显存瓶颈。
- **硬件使用证据**〔素材 #5/#6，需实测截图〕：推理时 `rocm-smi` GPU 占用/显存、llama.cpp `--n-gpu-layers` offload 日志。

## P9 · 本地化部署与量化策略 〔评分 3.2，7 分〕

- 一句核心论点：**量化把大模型塞进端侧，换可接受精度损失下的本地吞吐与能效。**
- llama.cpp（ROCm/HIP 或 Vulkan）运行量化模型：「LLM Qwen2.5-14B INT4(Q4_K_M) / Embedding bge-m3 / Rerank bge-reranker-v2-m3」。
- 选型理由：96G 统一内存内兼顾精度与吞吐，单机并发。

## P12 · 隐私保护与安全性 〔评分 4，15 分〕

> 一页一信息：四层若挤可拆为「本地部署」+「脱敏与访问控制」两页。

- 一句核心论点：**本地部署是隐私的根本保障，脱敏与最小权限是工程兜底。**

  2. **存储与访问控制 / 日志脱敏（5 分）**：身份证/卡号/手机号落盘前正则掩码；Demo 用脱敏编号 P101/P102；最小权限访问（加密如未实现则标"内网隔离+最小权限"）。
  3. **敏感领域合规（3 分）**：定位"分析辅助/线索发现"，处置由人工复核，不替代监管判定。
