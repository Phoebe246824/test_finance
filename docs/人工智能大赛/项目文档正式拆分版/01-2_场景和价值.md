# 1.2 场景和价值

## 1.2.1 应用场景

本项目主要面向银行零售风险管理中的反欺诈、反洗钱和贷前风控场景。系统可部署在银行内网、本地服务器、网点风控工作站或边缘节点中，对客户交易事件、风险文本、历史行为和知识库证据进行本地化分析。

典型应用场景如表 2 所示。

| 应用场景 | 典型风险问题 | 系统能力 |
|---|---|---|
| 个人账户异常交易监测 | 高频转账、资金拆分、多账户归集、异常收款方聚集 | 自动串联当前交易与历史事件，辅助发现反洗钱线索 |
| 信用卡与借记卡反欺诈 | 盗刷、陌生设备登录、异常消费、疑似套现 | 结合黑名单、设备线索和历史行为进行实时预警 |
| 消费贷和个人经营贷风控 | 虚假材料、资金用途异常、团伙申请 | 通过知识图谱发现客户、设备、账户和申请行为之间的关联风险 |
| 网点和远程银行复核 | 人工需要跨系统查询客户、账户、交易和规则 | 自动生成证据摘要和处置建议，提高人工复核效率 |
| 反洗钱调查中心 | 可疑交易证据分散，历史链路难以还原 | 通过历史事件回捞和图谱补图形成可解释证据链 |
| 银行内网本地风控节点 | 敏感数据不宜上传外部云端 | 支持端侧推理和本地存储，降低数据安全与合规风险 |

## 1.2.2 市场与业务价值

银行风险管理正从传统规则驱动逐步转向“规则 + 模型 + 知识 + 人工复核”的复合模式。随着大模型和智能体技术发展，金融机构希望利用 AI 提升风险识别效率，但同时必须满足数据安全、模型可控、证据可追溯和审计合规要求。

本项目的业务价值主要体现在以下方面：

1. 提升复杂风险识别能力。系统不只判断单条事件是否命中规则，还结合历史交易、黑名单、金融知识库和图谱关系进行综合研判。
2. 提高人工复核效率。系统可生成风险等级、证据摘要、关联历史事件和建议动作，减少人工在多个系统之间反复查询的时间。
3. 支持金融数据本地处理。量化大模型、向量模型、知识库和图谱服务均可部署在本地或银行内网，降低敏感数据外传风险。
4. 增强风险预警可解释性。系统能够展示黑名单命中、RAG 证据、图谱关系和历史回捞结果，便于风控人员复核。
5. 支持持续沉淀机构知识。低风险事件可作为客户行为基线，高风险事件可沉淀为案例样本，逐步形成机构级风险知识资产。

## 1.2.3 对比分析

与传统规则系统、中心化云端大模型方案和单次文本分类模型相比，本项目具有以下特点，具体如表 3 所示。

| 对比维度 | 传统规则系统 | 云端大模型分析 | 单次文本分类模型 | 本项目方案 |
|---|---|---|---|---|
| 部署方式 | 多为中心化后台 | 依赖外部云服务 | 可本地或云端部署 | 端侧/内网本地部署 |
| 数据隐私 | 数据集中处理 | 存在外传风险 | 取决于部署方式 | 敏感数据本地处理 |
| 风险识别方式 | 固定规则匹配 | 大模型文本推理 | 单条事件分类 | 多智能体协同研判 |
| 历史线索利用 | 依赖人工查询 | 需要额外接入数据 | 较弱 | Milvus 历史回捞 + Neo4j 补图 |
| 证据解释 | 命中规则为主 | 解释不稳定 | 解释有限 | RAG 证据 + 图谱关系 + 风险摘要 |
| 人工复核闭环 | 通常独立处理 | 需要二次开发 | 较弱 | 前端展示、审核动作和审计日志闭环 |

因此，本项目不仅是一个大模型问答系统，而是面向银行零售风控流程的智能体预警系统，强调业务闭环、可解释证据和端侧部署能力。
