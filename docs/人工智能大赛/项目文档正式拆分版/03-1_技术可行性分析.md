# 3.1 技术可行性分析

## 3.1.1 数据采集与样本构建可行性

项目初期不使用真实客户隐私数据，而采用脱敏模拟样本、公开金融风险案例和人工构造 Demo 事件。该方式既能覆盖银行零售风控中的典型风险模式，又能避免真实金融数据合规风险。

样本类型包括：

| 样本类型 | 示例 | 用途 |
|---|---|---|
| 正常交易样本 | 工资入账、日常消费、常用账户转账 | 构建低风险行为基线 |
| 黑名单命中样本 | 黑名单人员、风险关键词、历史高危事件样本 | 测试黑名单过滤能力 |
| 反洗钱样本 | 资金拆分、多账户归集、异常收款方聚集 | 测试历史回捞和组合风险识别 |
| 反欺诈样本 | 陌生设备登录、盗刷、异常消费 | 测试实时风险预警 |
| 贷前风控样本 | 资料异常、资金用途异常、团伙申请 | 测试知识图谱关联能力 |

所有样本进入系统前应进行字段脱敏，将姓名、手机号、身份证号、银行卡号等真实敏感字段替换为客户编号、账户编号或哈希标识。例如使用 `P101`、`A202` 等编号代替真实客户和账户。

数据流转过程如下：

```text
公开案例/模拟交易/脱敏样本
  -> 字段脱敏
  -> 事件标准化
  -> Milvus 事件库
  -> Neo4j 时序知识图谱
  -> RAGFlow 金融知识库
  -> 风险研判与报告生成
```

## 3.1.2 行业知识获取可行性

行业知识主要来自公开监管制度、公开金融风险案例、银行业务规则和团队整理的风险提示词模板。可纳入知识库的内容包括：

1. 反洗钱相关制度，例如客户身份识别、可疑交易报告、资金拆分识别等规则。
2. 银行零售业务知识，例如个人账户交易、信用卡风控、消费贷和个人经营贷流程。
3. 公开风险案例，例如电信诈骗资金流转、银行卡盗刷、虚假贷款申请等。
4. 项目内置规则，例如高频小额转账、陌生设备登录、黑名单关键词、异常收款方等。

这些文档可上传到 RAGFlow，由 bge-m3 进行向量化索引。风险分析时，系统根据当前事件召回相关知识片段，并使用 bge-reranker-v2-m3 对候选证据进行精排，最后将高相关证据输入风险评估智能体。

## 3.1.3 算力与硬件可行性

当前服务器配置如下：

| 项目 | 配置 |
|---|---|
| 操作系统 | Ubuntu 22.04.5 LTS (Jammy Jellyfish) |
| CPU | Intel Core i9-10900X @ 3.70GHz，4 核 |
| GPU | NVIDIA GeForce RTX 2080 Ti Rev. A |
| 显存 | 11264 MiB，约 11GB |

模型配置如下：

| 模型 | 作用 | 部署说明 |
|---|---|---|
| Gemma-4-12B-it Q4_K_M | 本地大语言模型 | 用于事件理解、分类、评估和报告生成 |
| bge-m3 | 向量模型 | 用于知识库、历史事件和黑名单样本召回 |
| bge-reranker-v2-m3 | 重排序模型 | 用于候选证据精排 |

Q4_K_M 量化格式可显著降低大模型部署资源需求，使 12B 级模型在本地服务器上进行 Demo 推理具备可行性。考虑到 RTX 2080 Ti 显存约 11GB，系统实际运行时需要采用以下策略：

- 控制上下文长度和单次输出长度。
- 限制并发请求数量。
- 将 LLM、embedding、rerank 服务分离部署或分时调用。
- 必要时采用 CPU/GPU 混合卸载。
- 记录显存峰值、CPU 内存峰值和推理速度，作为 Inference 指标。

## 3.1.4 系统工程可行性

项目已有较完整的工程结构：

| 目录或模块 | 功能 |
|---|---|
| `backend/app` | FastAPI 后端 API |
| `frontend` | Vue3 前端页面 |
| `blacklist` | Milvus 黑名单与事件存储 |
| `graphiti`、`graphiti_core` | Graphiti + Neo4j 图谱构建与检索 |
| `ragflow` | RAGFlow 文档上传与检索 |
| `trend_prediction` | 意图分析和趋势预测提示词 |
| `scripts` | Demo 样本、数据初始化和比赛报告脚本 |
| `tests` | 单元测试和回归测试 |

项目不需要从零开始搭建，而是在已有代码基础上完成模型接入、评测指标采集、图表绘制和比赛材料整理，实施风险可控。

## 3.1.5 技术可行性结论

综合数据、知识、模型、硬件和工程基础分析，本项目具备实施可行性：

1. 数据方面，可通过脱敏模拟样本和公开案例完成初赛验证。
2. 知识方面，可通过 RAGFlow 管理公开制度、案例和业务规则。
3. 模型方面，Gemma-4-12B-it Q4_K_M、bge-m3、bge-reranker-v2-m3 能覆盖推理、召回和精排需求。
4. 硬件方面，当前服务器可支持小批量 Demo 和量化推理验证。
5. 工程方面，项目已有后端、前端、向量库、图谱、知识库和测试脚本基础。

本节涉及的数据来源、知识来源、硬件条件和工程基础已通过文字与表格说明，正式文档不再额外绘制可行性流程图，以避免与系统架构图和风险研判流程图重复。
