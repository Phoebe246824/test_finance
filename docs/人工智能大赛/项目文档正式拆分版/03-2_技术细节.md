# 3.2 技术细节

## 3.2.1 系统总体架构

系统采用“前端交互层、智能体编排层、模型与知识层、端侧硬件层”的四层架构，整体结构如图 2 所示。

| 架构层 | 组成 | 作用 |
|---|---|---|
| 前端交互层 | Vue3、Vite、风险分析工作台、事件库、人物图谱、黑名单管理、系统状态页面 | 面向风控人员展示事件、风险结果、证据链和图谱关系 |
| 智能体编排层 | FastAPI、标准化流程、黑名单过滤、分类、检索、图谱构建、风险评估、历史回捞、报告生成 | 组织完整风险研判流程 |
| 模型与知识层 | Gemma-4-12B-it Q4_K_M、bge-m3、bge-reranker-v2-m3、RAGFlow、Milvus、Neo4j | 提供推理、向量召回、证据精排、知识库和图谱能力 |
| 端侧硬件层 | Ubuntu 服务器、Intel Core i9-10900X、NVIDIA RTX 2080 Ti 11GB | 支撑本地推理、检索和存储服务运行 |

系统核心链路如图 3 所示，可概括为：

```text
事件输入
  -> 事件标准化
  -> 黑名单三路过滤
  -> 风险分类
  -> RAG 检索与重排序
  -> 知识图谱构建
  -> 首次风险评估
  -> 高风险历史回捞
  -> 批量补图
  -> 二次风险研判
  -> 风险报告与人工复核
```

## 3.2.2 多智能体流程设计

项目将风控任务拆解为多个智能体或阶段，每个阶段只承担明确职责，降低单一模型直接生成最终结论带来的不可控风险。各阶段在图 3 中按执行顺序串联展示。

| 阶段 | 输入 | 输出 | 作用 |
|---|---|---|---|
| 事件标准化 | 原始金融事件文本 | 结构化事件对象 | 抽取客户、账户、金额、时间、行为描述和风险线索 |
| 黑名单过滤 | 结构化事件 | 命中结果 | 判断人员、关键词、历史高危事件样本是否命中 |
| 风险分类 | 事件文本和上下文 | 风险类别 | 判断反欺诈、反洗钱、贷前欺诈、异常交易等类别 |
| 检索增强 | 当前事件 | 知识库证据和历史事件 | 为风险评估提供外部依据 |
| 图谱构建 | 实体和关系 | Neo4j 节点与边 | 表达客户、账户、交易、设备和风险标签关系 |
| 首次评估 | 当前事件、证据、图谱上下文 | 首次风险等级和风险分 | 形成初步研判 |
| 历史回捞 | 高风险主体和语义线索 | 关联历史事件 | 补充组合风险上下文 |
| 二次研判 | 当前事件和历史补图结果 | 二次风险等级和证据链 | 识别资金拆分、团伙欺诈等组合风险 |
| 报告生成 | 风险评估结果 | 调查摘要和处置建议 | 输出给风控人员复核 |

## 3.2.3 本地大模型推理

系统计划加载 Gemma-4-12B-it Q4_K_M 量化模型作为核心大语言模型。模型主要承担事件理解、风险分类、证据归纳和报告生成等任务。

| 任务 | 输入 | 输出 | 控制方式 |
|---|---|---|---|
| 事件结构化 | 原始事件文本 | 客户、账户、金额、时间、行为等字段 | 使用固定 JSON Schema 约束输出 |
| 风险分类 | 事件和规则上下文 | 风险类别和简要理由 | 限定候选类别，减少自由发挥 |
| 风险评估 | 当前事件、RAG 证据、图谱上下文 | 风险分、风险等级、证据点 | 要求引用证据和规则依据 |
| 报告生成 | 风险评估结果 | 调查摘要、可疑点、处置建议 | 控制输出格式，便于前端展示 |

为降低幻觉风险，模型输出不作为唯一判断依据，而是结合黑名单命中、向量检索证据、知识图谱关系和风险规则共同形成结论。对于高风险事件，系统还会触发历史事件回捞和二次研判，避免只根据当前事件做出片面判断。

## 3.2.4 向量检索与重排序

系统使用 bge-m3 对金融制度、公开案例、历史事件和黑名单事件样本进行向量化。当前事件进入系统后，检索模块根据事件描述生成向量，在 Milvus 或 RAGFlow 检索相关候选证据。

向量召回与重排序流程如图 4 所示，可概括为：

```text
当前风险事件
  -> bge-m3 编码
  -> Milvus/RAGFlow 向量检索
  -> Top-K 候选证据
  -> bge-reranker-v2-m3 重排序
  -> Top-N 高相关证据
  -> 输入风险评估智能体
```

重排序模型 bge-reranker-v2-m3 用于判断“当前事件”和“候选证据”之间的相关性。相比只使用向量相似度，重排序可以减少语义相近但业务无关的证据，提高风险评估上下文质量。

预期评测指标如下：

| 指标 | 说明 | 记录方式 |
|---|---|---|
| Top-K 召回命中率 | 标注相关证据是否进入召回候选 | 人工标注测试样本后统计 |
| 重排序后 Top-3 有效率 | 前 3 条证据中有效证据比例 | 对比有无 reranker |
| 检索延迟 | 向量召回和重排序耗时 | 日志或脚本记录 |
| 噪声过滤率 | reranker 过滤掉的无关候选比例 | 对候选证据人工核验 |

## 3.2.5 RAGFlow 金融知识库

RAGFlow 用于管理金融制度、反洗钱规则、银行业务知识和风险案例。系统不直接让大模型凭空判断风险，而是先从知识库中检索相关依据，再由风险评估智能体结合证据生成结论。

知识库内容包括：

- 反洗钱制度和可疑交易识别规则。
- 银行个人账户交易与信用卡风控知识。
- 消费贷、个人经营贷和客户身份识别相关业务规则。
- 公开金融风险案例。
- 团队整理的演示规则和风险提示词。

RAGFlow 与 bge-m3、bge-reranker-v2-m3 结合后，能够形成“文档切分、语义召回、证据精排、模型引用”的检索增强链路。该链路与图 4 中的 RAG 检索与重排序流程一致。

## 3.2.6 知识图谱与历史回捞

系统使用 Graphiti + Neo4j 构建时序知识图谱，将银行风险事件中的实体和关系结构化表示。

主要节点包括：

| 节点类型 | 示例 |
|---|---|
| 客户 | 客户编号、风险标签 |
| 账户 | 银行账户、交易账户 |
| 交易 | 时间、金额、方向、摘要 |
| 设备 | 登录设备、设备指纹 |
| 收款方 | 收款账户、商户或个人 |
| 风险标签 | 黑名单命中、资金拆分、异常设备 |

主要关系包括：

| 关系类型 | 含义 |
|---|---|
| `OWNS` | 客户拥有账户 |
| `TRANSFER_TO` | 账户向另一账户转账 |
| `USES_DEVICE` | 客户或账户使用某设备 |
| `HIT_BLACKLIST` | 主体命中黑名单 |
| `RELATED_TO` | 当前事件与历史事件相关 |

当首次风险评估超过阈值时，系统从 Milvus events collection 中召回同客户、同账户或语义相关的历史事件，并将这些历史事件批量补充到 Neo4j 图谱中。二次研判时，模型可以看到更完整的交易链路和主体关系，从而识别资金拆分、多账户归集、团伙欺诈等组合风险。知识图谱与历史回捞机制如图 5 所示。

## 3.2.7 风险评分与人工复核

风险评估结果包括风险类别、风险等级、风险分数、命中规则、证据摘要、历史线索和建议动作。可采用如下风险等级：

| 风险等级 | 分数区间 | 处置建议 |
|---|---:|---|
| 低风险 | 0-39 | 入库留存，作为客户行为基线 |
| 中风险 | 40-69 | 提示人工关注，补充核验材料 |
| 高风险 | 70-100 | 触发预警，进入人工复核或反洗钱调查 |

人工复核闭环包括：

```text
AI 风险预警
  -> 风控人员查看事件详情
  -> 查看黑名单命中、RAG 证据、图谱关系和历史事件
  -> 人工确认、驳回或补充材料
  -> 审核动作写入审计日志
  -> 后续用于规则优化和样本沉淀
```

后端采用 FastAPI，提供风险分析、事件管理、图谱查询、黑名单管理、系统状态和设置等接口。前端采用 Vue3 + Vite，实现面向风控人员的交互界面。

前端核心页面包括：

| 页面 | 功能 |

| 风险分析工作台 | 输入事件并查看风险评估结果 |
| 风控总览 | 查看风险事件统计和趋势 |

## 3.2.10 核心技术论证

本项目的核心技术路线具有互补性：

1. Gemma-4-12B-it Q4_K_M 负责复杂语言理解和报告生成，但不单独承担全部判断责任。
2. bge-m3 负责将制度、案例和历史事件转化为可检索向量，为模型提供外部知识。
3. bge-reranker-v2-m3 负责提升候选证据排序质量，降低无关证据干扰。
4. Milvus 负责高效存储和召回历史事件、黑名单样本和向量数据。
5. Neo4j 负责表达客户、账户、交易和设备之间的结构化关系。
6. RAGFlow 负责文档管理和知识库检索，使风险评估可引用制度与案例依据。

因此，系统能够同时处理文本理解、语义检索、关系推理和业务闭环，适合银行零售反欺诈与反洗钱预警场景。正式文档中保留图 2 至图 5 与表 4 即可覆盖本节核心技术，不再额外绘制风险评分闭环图。
