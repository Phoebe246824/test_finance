# 1.1 背景和基础

## 1.1.1 项目背景

随着银行零售业务线上化、实时化和多渠道化程度不断提高，个人账户转账、银行卡消费、消费贷申请、远程开户、电子渠道登录、设备指纹变更等业务事件快速增长。传统反欺诈与反洗钱系统通常依赖规则引擎、人工复核和中心化模型，能够覆盖部分已知风险模式，但面对多源、隐蔽、渐进式的风险行为时仍存在明显不足。

在银行零售风控中，很多可疑行为并不是由单笔交易直接暴露，而是由多笔交易、多类主体关系和历史上下文共同形成。例如，某客户单笔小额转账可能并不异常，但若短时间内出现多账户归集、资金拆分、陌生设备登录、异常收款方聚集等现象，则可能构成反洗钱或欺诈风险。传统规则系统容易关注单次事件，难以自动串联历史线索和关系网络。

同时，银行客户身份、账户流水、交易关系、设备信息和贷款材料属于高度敏感数据。若直接依赖外部云端大模型进行分析，可能带来隐私泄露、合规审计和网络可用性风险。因此，面向银行内网、网点边缘节点或本地服务器的端侧 AI 风控系统具有较强现实意义。

本项目由上述业务痛点出发，提出一种端侧部署的多智能体风险预警方案：在本地服务器上部署量化大模型、向量模型、重排序模型、向量数据库和知识图谱系统，通过多智能体协同完成事件理解、知识检索、图谱推理、历史回捞和风险预警。

## 1.1.2 已有工作基础

项目已有工程基础位于 `/Users/phoebe/project/test_finance`。系统已完成从后端服务、前端页面到核心算法模块的初步搭建，具备继续完善和参赛演示的基础。

已有功能包括：

| 模块 | 已有基础 | 作用 |
|---|---|---|
| 后端服务 | FastAPI API | 提供风险分析、事件查询、黑名单管理、系统状态等接口 |
| 前端系统 | Vue3 + Vite | 提供风险看板、事件库、人物图谱、黑名单管理和设置页面 |
| 向量数据库 | Milvus | 存储事件、黑名单人员、风险关键词、事件样本和审核动作 |
| 知识图谱 | Graphiti + Neo4j | 构建客户、账户、交易、设备和风险标签之间的时序关系 |
| 知识库 | RAGFlow | 管理反洗钱制度、银行业务规则和风险案例等文档 |
| 大模型流程 | Gemma-4-12B-it Q4_K_M | 支持事件理解、风险分类、证据摘要和处置建议生成 |
| 向量与重排序 | bge-m3、bge-reranker-v2-m3 | 支持语义召回和证据精排 |
| 测试脚本 | tests、scripts | 支持 Demo 样本、数据初始化和回归测试 |

项目当前服务器与运行环境如表 1 所示。

| 项目 | 配置 |
|---|---|
| 操作系统 | Ubuntu 22.04.5 LTS (Jammy Jellyfish) |

| GPU | NVIDIA GeForce RTX 2080 Ti Rev. A |
| 显存 | 11264 MiB，约 11GB |
| 大语言模型 | Gemma-4-12B-it Q4_K_M 量化模型 |
| 向量模型 | bge-m3 |
| 重排序模型 | bge-reranker-v2-m3 |

在已有项目基础上，团队将进一步完成模型接入、实验评测、技术文档、演示 PPT 和演示视频，形成符合比赛要求的初赛作品材料。
