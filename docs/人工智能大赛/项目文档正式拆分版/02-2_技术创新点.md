# 2.2 技术创新点

比赛提交规范要求对作品创新性进行充分严谨的论证，并通过技术调研与已有工作进行对比。本项目的创新性不在于单独提出一个全新模型，而在于将端侧量化大模型、多智能体流程、RAG 检索增强、时序知识图谱和银行零售风控业务闭环结合起来，形成面向金融隐私场景的本地化风险预警系统。项目核心创新点如图 1 所示。

## 2.2.1 创新点一：面向银行零售风控的端侧多智能体协同架构

传统风控系统通常以规则引擎和人工复核为主，部分系统引入机器学习模型后，也多集中在单一分类或评分任务。本项目将银行风险研判流程拆分为多个智能体或处理阶段：

- 事件标准化智能体：从原始文本中抽取客户、账户、金额、时间、设备、交易行为等结构化字段。
- 黑名单过滤阶段：对人员、关键词和历史事件样本进行三路匹配。
- 风险分类智能体：判断事件属于反欺诈、反洗钱、贷前欺诈或异常交易等类别。
- 检索增强阶段：从 RAGFlow 金融知识库和 Milvus 历史事件中召回相关证据。
- 图谱构建阶段：将客户、账户、交易、设备和风险标签写入 Neo4j 图谱。
- 风险评估智能体：结合当前事件、检索证据和图谱上下文输出风险等级。
- 历史回捞阶段：在高风险触发后召回同客户、同账户或语义相关历史事件。
- 二次研判智能体：基于补图后的历史关系进行组合风险判断。
- 报告智能体：生成调查摘要、可疑点和处置建议。

该架构使系统从“单模型一次判断”转向“多阶段证据融合”，更贴近银行反欺诈和反洗钱工作流。

## 2.2.2 创新点二：RAG 与时序知识图谱融合的证据增强机制

大语言模型在金融风控中存在事实依据不足、解释不稳定、难以追溯等问题。为提升模型输出可信度，本项目引入两类证据增强机制：

1. RAG 文本证据。系统通过 RAGFlow 管理监管制度、反洗钱规则、银行业务知识和公开风险案例，并使用 bge-m3 进行向量召回、bge-reranker-v2-m3 进行重排序。
2. 时序图谱证据。系统通过 Graphiti + Neo4j 表达客户、账户、交易、设备、风险标签之间的关系，并保留事件时间顺序。

RAG 适合提供制度和案例依据，知识图谱适合表达主体关系和历史链路。两者结合后，风险评估智能体可以同时获得“文本依据”和“结构化关系依据”，从而提升结果可解释性。

## 2.2.3 创新点三：历史事件回捞与二次研判机制

反洗钱和欺诈风险往往呈现“单笔弱信号、多笔强关联”的特点。传统规则系统若只关注当前事件，容易漏掉历史上分散出现的可疑行为。

本项目将低风险事件也写入 Milvus events collection，作为客户行为基线和历史上下文。当后续出现高风险触发事件时，系统自动从 Milvus 中召回同客户、同账户或语义相关的历史事件，并将其批量补充到 Neo4j 图谱中，再进行二次研判。

该机制能够发现以下组合风险：

- 多笔小额资金拆分后集中转出。
- 同一设备关联多个客户或账户。
- 同一收款方与多个异常客户存在资金往来。
- 当前交易与历史贷款申请、黑名单关键词或可疑案例存在语义相似性。

## 2.2.4 创新点四：量化大模型在端侧金融风控中的应用

本项目采用 Gemma-4-12B-it Q4_K_M 量化模型作为本地大语言模型，并在 Ubuntu 22.04.5 LTS、Intel Core i9-10900X、NVIDIA GeForce RTX 2080 Ti 11GB 显存服务器上进行部署验证。量化模型相比全精度模型可降低资源占用，使本地 Demo 和端侧原型具备可行性。

端侧部署带来的价值包括：

1. 客户隐私数据在本地或银行内网处理，降低外部云端传输风险。
2. 在网络不稳定或外部服务不可用时，仍可完成基本风险分析。
3. 便于在银行网点、分支机构或专网环境中部署。
4. 可结合本地 Milvus、Neo4j 和 RAGFlow 持续沉淀机构风险知识。

## 2.2.5 创新点五：可视化、可复核的风险预警闭环

本项目不是只输出风险文本结论，而是通过前端页面呈现风险评分、命中规则、检索证据、历史事件和图谱关系。风控人员可以查看事件详情、人物图谱、黑名单命中原因、模型摘要和建议动作，并进行人工复核。

该闭环符合金融风控“AI 辅助、人机协同、可审计可追溯”的实际需求，能够减少模型黑箱问题，提高业务可接受度。

本项目与已有方案的对比如表 3 所示。

| 维度 | 传统规则系统 | 通用 RAG 问答系统 | 单模型文本分类系统 | 本项目 |
|---|---|---|---|---|
| 目标场景 | 已知规则风险拦截 | 文档问答 | 文本类别判断 | 银行零售反欺诈与反洗钱预警 |
| 部署方式 | 中心化系统 | 多依赖云端或独立服务 | 灵活 | 本地/端侧部署 |
| 推理方式 | 规则匹配 | 文本检索 + 生成 | 单次分类 | 多智能体协同推理 |
| 历史线索 | 需要人工查询 | 通常较弱 | 通常不处理 | 自动历史回捞与补图 |
| 结构化关系 | 较弱 | 较弱 | 较弱 | Neo4j 时序知识图谱 |
| 证据可解释性 | 命中规则可解释 | 依赖召回文本 | 较弱 | 规则 + RAG + 图谱 + 历史事件 |
| 隐私保护 | 取决于部署 | 若用云端有外传风险 | 取决于部署 | 敏感数据本地处理 |
