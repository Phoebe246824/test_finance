# 1.3 所需支持

项目实施需要算力、硬件、数据、行业知识、培训和评测等方面的支持。当前项目已具备基础服务器和初步工程代码，但要形成可展示、可量化、可复现的参赛作品，仍需进一步补充实验数据、行业样本和演示材料。

## 1.3.1 当前具备条件

当前服务器配置已在表 1 中列出，本节进一步说明项目实施所需支持。

| 项目 | 配置 |
|---|---|
| 操作系统 | Ubuntu 22.04.5 LTS (Jammy Jellyfish) |
| CPU | Intel Core i9-10900X @ 3.70GHz，4 核 |
| GPU | NVIDIA GeForce RTX 2080 Ti Rev. A |
| 显存 | 11264 MiB，约 11GB |

当前模型方案如下：

| 模型类型 | 模型名称 | 用途 |
|---|---|---|
| 大语言模型 | Gemma-4-12B-it Q4_K_M 量化模型 | 事件理解、风险分类、风险评估和报告生成 |
| 向量模型 | bge-m3 | 金融知识库、历史事件和黑名单样本语义召回 |
| 重排序模型 | bge-reranker-v2-m3 | 对召回证据进行相关性精排 |

RTX 2080 Ti 11GB 显存适合开展量化模型推理、向量模型服务和小批量 Demo 验证。由于 Gemma-4-12B-it Q4_K_M 模型规模较大，实际部署时需重点关注上下文长度、并发数、显存占用、CPU 内存占用和推理速度。项目将通过量化推理、控制 max tokens、降低并发、分离 embedding/rerank 服务或必要时采用 CPU/GPU 混合卸载等方式保证系统稳定运行。

## 1.3.2 所需支持内容

| 支持类型 | 具体需求 | 用途 |
|---|---|---|
| 算力支持 | 支持本地运行量化大模型、向量模型和重排序模型的服务器或端侧 AI 设备 | 完成模型部署、推理评测和 Demo 演示 |
| 硬件支持 | GPU 显存、CPU 内存、磁盘和稳定网络环境 | 支持 Milvus、Neo4j、RAGFlow、FastAPI、Vue3 等组件并行运行 |
| 数据支持 | 脱敏交易样本、模拟风险事件、公开反洗钱案例 | 构建测试集、演示样本和风险识别评估数据 |
| 知识支持 | 银行反欺诈、反洗钱、贷前风控规则与监管制度 | 建设 RAGFlow 金融知识库和风险评估依据 |
| 培训支持 | 模型量化部署、RAG、知识图谱、端侧 AI 优化相关指导 | 提升系统稳定性和比赛展示质量 |
| 评测支持 | 延迟、吞吐、显存占用、召回率、准确率等评测方法 | 完成符合比赛要求的 Inference 效果和指标展示 |

## 1.3.3 风险与应对

| 风险 | 表现 | 应对方式 |
|---|---|---|
| 模型资源占用较高 | 12B 量化模型在长上下文或并发场景下仍可能占用较多显存或内存 | 控制上下文长度、限制并发、分离模型服务、必要时 CPU/GPU 混合卸载 |
| 测试样本不足 | 难以充分证明反欺诈和反洗钱效果 | 构建覆盖低风险、黑名单命中、资金拆分、贷款欺诈等多类样本 |
| 证据召回噪声 | RAG 召回结果可能与事件不完全相关 | 使用 bge-reranker-v2-m3 进行精排，并保留人工复核入口 |
| 图谱复杂度上升 | 多事件补图可能影响查询和展示速度 | 控制 Demo 数据规模，按客户、账户和时间窗口进行筛选 |
| 指标缺失 | 文档无法体现 Inference 效果 | 使用脚本记录延迟、tokens/s、显存、召回率和准确率 |

上述支持需求和风险应对已在本节表格中说明，正式项目文档中无需另设独立图表。
