# 2.1 整体目标

参赛期间，本项目计划完成一个可演示、可复现、可评估的端侧金融风控多智能体原型系统，并形成符合比赛提交规范的项目文档、作品简介、演示视频和辅助材料。

## 2.1.1 系统目标

系统目标包括：

1. 完成端侧模型部署与系统接入。使用 Gemma-4-12B-it Q4_K_M 量化模型作为本地大语言模型，使用 bge-m3 作为向量模型，使用 bge-reranker-v2-m3 作为重排序模型，形成本地推理、语义召回和证据精排能力。
2. 完成银行零售风险事件处理闭环。系统能够从原始事件文本出发，完成事件标准化、黑名单过滤、风险分类、知识库检索、图谱构建、风险评分、历史回捞、二次研判和报告生成。
3. 完成可视化原型系统。前端提供风险分析工作台、事件库、人物图谱、黑名单管理、风险规则、审计日志和系统状态等页面，用于比赛现场展示。
4. 完成可解释风险预警。系统输出不只包含风险等级，还包含黑名单命中、知识库证据、图谱关系、历史事件线索和处置建议。
5. 完成 Demo 测试样本与实验报告。构建覆盖低风险、黑名单命中、反洗钱可疑交易、贷款欺诈等场景的测试样本，统计端到端延迟、资源占用、风险识别效果和召回效果。

按照作品提交规范，团队将准备以下材料：

| 材料 | 要求 | 项目准备内容 |
|---|---|---|
| 参赛作品简介 | 300 字以内，PDF 格式 | 凝练说明项目场景、技术路线和价值 |
| 项目文档 | 按模板详细阐述，PDF 格式 | 完成本目录各章节并插入图表和实验指标 |

| 其他辅助材料 | ZIP 格式，文件不超过 200M | 项目代码、截图、实验记录、PPT 或辅助说明 |

## 2.1.3 阶段目标

| 阶段 | 主要任务 | 交付成果 |
|---|---|---|
| 第一阶段：项目梳理 | 梳理比赛要求、确定项目题目、明确业务场景 | 项目定位、技术路线、文档框架 |
| 第二阶段：模型联调 | 接入 Gemma-4-12B-it Q4_K_M、bge-m3、bge-reranker-v2-m3 | 本地推理与检索链路 |
| 第三阶段：系统完善 | 完善风险事件闭环、历史回捞、图谱展示和报告生成 | 可演示系统原型 |
| 第四阶段：实验评测 | 构建测试样本，采集延迟、tokens/s、显存占用、召回率等指标 | 实验结果表和截图 |
| 第五阶段：材料提交 | 完成项目文档、作品简介、PPT、视频和辅助材料 | 初赛提交材料 |

## 2.1.4 预期验收指标

| 类型 | 指标 | 预期说明 |
|---|---|---|
| 功能完整性 | 是否完成端到端风险研判流程 | 从事件输入到风险报告输出可完整演示 |
| 推理效果 | 单条事件处理延迟、tokens/s、首 token 延迟 | 通过本地部署环境实测补充 |
| 资源占用 | GPU 显存峰值、CPU 内存峰值 | 通过 `nvidia-smi` 和系统监控采集 |
| 检索效果 | bge-m3 Top-K 召回命中率 | 在标注 Demo 样本中统计 |
| 精排效果 | reranker 后 Top-3 有效证据比例 | 对比只召回和召回+重排序 |
| 风控效果 | 高风险识别准确率、历史回捞有效率 | 基于人工标注样本统计 |
| 可解释性 | 是否输出证据链和图谱关系 | 前端详情页和图谱页面展示 |

本节的阶段目标和验收指标已通过表格呈现，正式项目文档中无需额外绘制项目目标图。
