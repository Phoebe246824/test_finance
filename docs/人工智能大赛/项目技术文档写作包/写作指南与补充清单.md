# 写作指南与补充清单

## 总体写法

这份项目技术文档建议采用“问题痛点 -> 系统方案 -> 技术创新 -> 可行性和实验 -> 计划分工”的逻辑。比赛文档不宜只写模型名称，要突出端侧 AI 对银行零售风控的价值：隐私数据本地处理、弱网可用、低延迟预警、历史线索自动串联、人工复核可解释。

题目建议使用：

```text
基于端侧 AI 的银行零售反欺诈与反洗钱风险多智能体预警系统
```

## 各章节写作要点

| 章节 | 写什么 | 建议材料 |
|---|---|---|
| 1.1 背景和基础 | 银行零售反欺诈、反洗钱、贷前风控痛点；团队已有代码、服务器和 Demo 基础 | 项目 README、前端截图、Demo 流程截图、软硬件环境表 |
| 1.2 场景和价值 | 面向银行网点、远程银行、反洗钱中心、信用卡风控 | 行业痛点对比表、应用场景价值表、传统方案对比图 |

## 已知服务器与模型配置

正式文档中可以直接使用以下配置表：

| 项目 | 配置 |
|---|---|
| 操作系统 | Ubuntu 22.04.5 LTS (Jammy Jellyfish) |
| CPU | Intel Core i9-10900X @ 3.70GHz，4 核 |
| GPU | NVIDIA GeForce RTX 2080 Ti Rev. A |
| 显存 | 11264 MiB，约 11GB |
| 大语言模型 | Qwen3.6-35B-A3B Q6_K_M 量化模型 |
| 向量模型 | bge-m3 |
| 重排序模型 | bge-reranker-v2-m3 |

写作提醒：RTX 2080 Ti 11GB 可以支撑小批量 Demo 和量化模型验证，但 Qwen3.6-35B-A3B Q6_K_M 规模较大，文档里建议写“通过量化、控制上下文长度、限制并发、必要时 CPU/GPU 混合卸载保证运行稳定”，不要写成无限制高并发部署。

## 写作注意事项

- 不要把项目写成单纯聊天机器人，要强调“风控预警系统”和“多智能体业务闭环”。
- 不要只说“使用大模型”，要写清楚模型在每个阶段解决什么问题。
- 没有实测的数据先写“预期指标”或“待实验验证”，正式提交前再替换。
- 金融数据要统一写“脱敏样本、模拟交易、公开制度文档”，避免暗示使用真实客户隐私数据。
- 技术创新点要和传统方案对比：传统规则引擎、中心化云端大模型、单次文本分类模型。
