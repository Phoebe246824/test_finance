# 基于端侧 AI 的银行零售反欺诈与反洗钱风险多智能体预警系统

## 1 项目概况

### 1.1 背景和基础

随着银行零售业务线上化程度不断提高，个人账户转账、银行卡消费、消费贷申请、远程开户、电子渠道登录等业务产生了大量实时事件。传统反欺诈与反洗钱系统主要依赖规则引擎、人工审核和中心化后台模型，能够覆盖部分已知风险模式，但在复杂组合风险、跨事件历史线索串联、可疑主体关系发现和低延迟本地处置方面仍存在不足。

一方面，反欺诈与反洗钱事件往往具有“单笔不明显、多笔组合异常”的特点。例如，客户短时间内出现多账户资金拆分、陌生设备登录、异常收款方聚集、贷款资料与交易行为不一致等现象时，单条事件可能无法触发高危规则，但多条历史事件组合后会形成明显风险证据。另一方面，银行客户身份信息、账户流水、交易关系和贷前材料具有高度敏感性，直接上传外部云端模型会带来合规和隐私风险。因此，面向银行内网、网点边缘节点或本地工作站的端侧 AI 风控系统具有较强现实需求。

本项目以“基于端侧 AI 的银行零售反欺诈与反洗钱风险多智能体预警系统”为题，围绕银行零售场景构建一个本地化、多智能体、可解释的风险预警原型。系统基于项目目录 `/Users/phoebe/project/test_finance` 已完成初步工程实现，现有基础包括：

- FastAPI 后端与 Vue3 前端，支持风险分析、事件库、人物图谱、黑名单管理、审计日志和系统状态展示。
- Milvus 向量数据库，用于事件存储、黑名单人员、风险关键词、黑名单事件样本和语义召回。
- Graphiti + Neo4j 时序知识图谱，用于表达客户、账户、交易、设备、风险标签之间的关系。
- RAGFlow 金融知识库接入，用于管理和检索反洗钱制度、银行业务规则、风险案例等文档。
- 本地模型方案采用 Qwen3.6-35B-A3B Q6_K_M 量化大语言模型，向量模型采用 bge-m3，重排序模型采用 bge-reranker-v2-m3。
- 现有代码包含标准化、黑名单过滤、分类、图谱构建、风险评估、历史事件回捞、趋势预测和报告生成等流程模块。

### 1.2 场景和价值

本项目主要面向银行零售风险管理中的反欺诈、反洗钱和贷前风控场景，典型应用包括：

| 应用场景 | 风险问题 | 系统价值 |
|---|---|---|
| 个人账户异常交易监测 | 高频转账、资金拆分、异常收款方聚集 | 自动识别可疑交易链路，辅助反洗钱调查 |
| 信用卡与借记卡反欺诈 | 盗刷、陌生设备登录、异常消费行为 | 结合历史行为与黑名单信息进行实时预警 |
| 消费贷和个人经营贷风控 | 资料异常、资金用途异常、团伙申请 | 通过图谱发现主体、设备、账户之间的关联风险 |
| 网点和远程银行人工复核 | 人工需要查多系统、多材料 | 自动生成证据摘要和处置建议，提高审核效率 |
| 银行内网本地风控节点 | 敏感数据不宜上传外部云端 | 支持端侧部署，降低隐私和合规风险 |

与传统方案相比，本项目的价值体现在四个方面：

1. 从单条规则判断转向多源证据融合。系统不仅判断关键词或黑名单命中，还结合历史事件、金融知识库、知识图谱关系和大模型推理结果进行综合评估。
2. 从中心化云端推理转向端侧本地智能。客户隐私数据、交易文本和图谱关系在本地或银行内网处理，适合金融数据安全要求较高的场景。
3. 从一次性分类转向多智能体闭环研判。系统包含标准化、分类、检索、图谱、风险评估、历史回捞、二次研判和报告生成等阶段，更贴近真实风控流程。
4. 从不可解释告警转向证据链预警。系统能够展示黑名单命中原因、知识库证据、历史交易线索和图谱关联关系，便于人工复核。

### 2.2 技术创新点

本项目的技术创新点主要包括：

#### 2.2.1 面向银行零售风控的端侧多智能体协同架构

项目将银行反欺诈与反洗钱流程拆解为多个智能体或处理阶段，包括事件标准化、黑名单过滤、风险分类、知识检索、图谱构建、风险评估、历史回捞、二次研判和报告生成。相比单一模型直接输出结论，多智能体架构能够将复杂任务分解为可解释、可追踪的子任务，更符合银行风控业务流程。

#### 2.2.2 RAG 与时序知识图谱融合的证据增强机制

系统同时使用 RAGFlow 金融知识库、Milvus 向量检索和 Graphiti + Neo4j 时序知识图谱。RAG 负责提供监管制度、风险案例和业务规则等文本证据，知识图谱负责表达客户、账户、设备、交易和风险标签之间的结构化关系。两类证据共同输入风险评估智能体，提高预警结果的可解释性和稳定性。

#### 2.2.3 历史事件回捞与二次研判机制

传统规则系统往往只根据当前事件触发告警，容易忽略多笔低风险事件累积形成的组合风险。本项目将低风险事件也写入 Milvus events collection，当后续出现高风险触发事件时，系统会按同客户、同账户和语义相似度召回历史事件，批量补充到知识图谱后进行二次研判，从而发现更隐蔽的反洗钱和欺诈链路。

#### 2.2.4 量化大模型在端侧金融风控中的应用

项目计划加载 Qwen3.6-35B-A3B Q6_K_M 量化模型，并结合 bge-m3 和 bge-reranker-v2-m3 实现本地化语义理解、证据召回和精排。相比云端大模型方案，本地量化部署更适合金融隐私数据处理、弱网环境和银行内网部署。

#### 2.2.5 可视化、可复核的风险预警闭环

系统前端提供事件详情、人物图谱、黑名单管理、审计日志和系统状态等页面。风控人员不仅能看到风险分数，还能查看命中规则、相关历史事件、图谱关系和模型生成的调查摘要，并进行人工复核，形成“AI 预警 + 人工确认”的闭环。

## 3 实施方案

### 3.1 技术可行性分析

#### 3.1.1 数据采集与样本构建可行性

项目初期不使用真实客户隐私数据，而采用脱敏模拟样本、公开金融风险案例和人工构造的 Demo 事件。样本类型包括正常工资入账、日常消费、陌生设备登录、异常转账、资金拆分、多账户归集、贷款资料异常、黑名单人员命中等。通过统一事件格式保存客户编号、账户编号、交易金额、时间、行为描述和风险标签，既能满足比赛演示需要，又能避免真实金融数据合规风险。

后续如有条件，可在银行或实验平台提供的脱敏数据集上进行扩展验证。所有真实敏感字段应在进入系统前完成脱敏处理，例如将姓名、手机号、身份证号、银行卡号替换为客户编号、账户编号或哈希标识。

#### 3.1.2 行业知识获取可行性

行业知识主要来自三类来源：

1. 公开监管制度和反洗钱规则，如客户身份识别、可疑交易报告、资金拆分识别等制度材料。
2. 公开金融风险案例和银行业务材料，如电信诈骗资金流转、银行卡盗刷、虚假贷款申请等案例。
3. 团队根据业务逻辑整理的风险规则和提示词模板，如高频小额转账、陌生设备登录、黑名单关键词、异常收款方等。

这些资料可以上传至 RAGFlow 金融知识库，由 bge-m3 进行向量化索引，并在风险评估时检索相关证据。重排序模型 bge-reranker-v2-m3 用于对候选证据进行精排，提升证据相关性。

项目采用端侧量化大模型部署思路。当前实验服务器操作系统为 Ubuntu 22.04.5 LTS，CPU 为 Intel Core i9-10900X @ 3.70GHz 4 核，GPU 为 NVIDIA GeForce RTX 2080 Ti Rev. ### 3.2 技术细节

#### 3.2.1 系统总体架构

系统采用“前端交互层、智能体编排层、模型与知识层、端侧硬件层”的四层架构：

1. 前端交互层：由 Vue3 实现风险分析工作台、事件库、人物图谱、黑名单管理、风险规则、审计日志和系统状态等页面。
2. 智能体编排层：由 FastAPI 后端和业务流程模块组织事件标准化、黑名单过滤、分类、图谱构建、检索增强、风险评估、历史回捞、二次研判和报告生成。
3. 模型与知识层：包括 Qwen3.6-35B-A3B Q6_K_M、本地 bge-m3、bge-reranker-v2-m3、RAGFlow 金融知识库、Milvus 向量库和 Neo4j 图数据库。
4. 端侧硬件层：由本地 CPU、GPU、NPU、统一内存和本地存储提供推理、检索、图谱查询和系统服务能力。

```text
  -> 二次风险研判
  -> 输出风险等级、证据链、处置建议和可视化结果
```

#### 3.2.2 本地大模型推理

系统计划加载 Qwen3.6-35B-A3B Q6_K_M 量化模型作为核心大语言模型。该模型主要承担以下任务：

- 将自然语言事件描述转化为结构化事件。
- 判断风险类别，如反欺诈、反洗钱、贷前欺诈、异常交易等。
- 根据检索证据和图谱上下文进行风险评分。
- 输出调查摘要、可疑点、处置建议和趋势分析。

为了降低幻觉风险，模型输出不直接作为唯一判断依据，而是结合黑名单命中、向量检索证据、知识图谱关系和风险规则共同形成结论。

#### 3.2.3 向量检索与重排序

系统使用 bge-m3 作为向量模型，对金融制度文档、风险案例、历史事件和黑名单事件样本进行向量化。检索阶段根据当前事件描述召回语义相关候选证据。

在召回结果基础上，系统使用 bge-reranker-v2-m3 进行重排序。重排序模型接收“当前事件 + 候选证据”对，输出相关性分数，从而筛除语义相近但业务无关的噪声证据。预期技术指标包括：

| 指标 | 预期目标 | 说明 |
|---|---:|---|
| Top-K 召回命中率 | 待实验验证 | 在标注样本中统计相关证据是否进入召回列表 |
| 重排序后 Top-3 相关率 | 待实验验证 | 统计前 3 条证据中有效证据比例 |
| 检索延迟 | 待实验验证 | 记录向量召回和 rerank 的平均耗时 |

#### 3.2.4 知识图谱与历史回捞

系统使用 Graphiti + Neo4j 构建时序知识图谱，将客户、账户、交易、设备、风险标签、黑名单信息等抽象为节点和边。图谱能够展示同一客户在不同时间的交易行为，也能发现不同客户之间共享账户、设备或收款方的关联风险。

当首次风险评估超过阈值时，系统从 Milvus events collection 中召回同客户、同账户或语义相关的历史事件，并将这些事件批量补充到图谱中。二次研判阶段将当前事件和历史事件一起输入风险评估智能体，用于识别资金拆分、短期多笔交易、团伙欺诈等组合风险。

#### 3.2.5 风险评分与人工复核

风险评估结果包括风险类别、风险等级、风险分数、命中规则、证据摘要和建议动作。系统可按照风险分数将事件分为低风险、中风险和高风险：

| 风险等级 | 示例阈值 | 建议动作 |
|---|---:|---|
| 低风险 | 0-39 | 入库留存，作为客户行为基线 |
| 中风险 | 40-69 | 提示人工关注，补充核验材料 |
| 高风险 | 70-100 | 触发预警，进入人工复核或反洗钱调查 |

实际阈值可根据测试结果和业务要求调整。前端页面支持查看事件详情和图谱关系，便于审核人员进行人工确认。
