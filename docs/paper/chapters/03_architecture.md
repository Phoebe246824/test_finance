# 3 系统总体架构

## 3.1 总体架构

Sentinel Edge 采用前后端分离和本地工具协同的架构。前端使用 Vue3 构建风险分析、事件库、事件详情、人物图谱、黑名单管理、系统状态和总览页面[8]；后端使用 FastAPI 提供事件分析、图谱查询、黑名单管理、人工复核和系统健康检查接口[7]；核心流程由 CrewAI Flow 编排，其中事件标准化、事件分类、风险评估、意图分析和趋势预测由 CrewAI Agent 完成，黑名单过滤、图谱构建、历史回捞和业务持久化由本地工具服务完成。

系统总体架构如图 1 所示。系统底层依赖本地部署组件：Redis 用于人员黑名单、关键词黑名单和高危事件样本的快速过滤；Milvus 用于事件向量暂存和相似历史事件召回[5]；Neo4j 用于存储客户、账户、商户、设备、事件和风险信号之间的关系[6]；SQLite 用于保存 Web 侧事件结果、趋势报告和人工复核动作。模型层包括通过 llama.cpp 部署的 Qwen3.6-35B-A3B 大模型、通过 vLLM 部署的 BGE M3 Embedding 和 BGE Reranker v2-m3。硬件层基于 AMD 锐龙 AI MAX+ 平台，将 GPU 用于量化 LLM 生成式推理，NPU 用于向量化和重排推理，CPU 用于流程编排、OpenAI 兼容接口调用、规则逻辑和数据库访问，统一内存支撑多服务并行。

## 3.2 端到端数据流

系统端到端分析流程如图 2 所示，具体步骤如下：

1. 用户在风险分析页输入金融事件文本，或从 Demo case 中选择样例。
2. 事件标准化模块抽取客户、账户、商户、设备、金额、时间、地点和风险信号。
3. 黑名单过滤模块查询人员黑名单、关键词黑名单和高危事件样本。
4. 未命中高危规则的事件按低风险展示，并写入 Milvus 暂存池，作为后续历史上下文。
5. 命中高危规则或出现明显风险信号的事件进入事件分类、图谱构建和风险评估流程。
6. 风险评估模块输出 `risk_score`、`risk_level` 和多维度分数。
7. 高风险事件触发历史回捞，从 Milvus 中检索语义相似或主体相关的历史事件。
8. 通过过滤的历史事件被补入 Neo4j，形成更完整的风险关系图谱。
9. 趋势预测模块基于当前事件、图谱上下文和历史事件生成趋势报告与处置建议。
10. 前端展示风险等级、黑名单命中、关系图谱、趋势报告和人工复核动作。

## 3.3 数据存储分工

系统关键数据组件的分工如表 2 所示。该设计将规则过滤、向量召回、关系证据和业务结果分层存储，既便于本地部署，也便于后续审计和迁移。

**表 2 系统数据组件分工**

| 模块 | 技术选择 | 存储内容 | 作用 |
|---|---|---|---|
| 黑名单过滤 | Redis | 人员、关键词、高危事件样本 | 快速过滤显性高危线索 |
| 向量暂存 | Milvus | 低风险事件向量、事件摘要、实体信息 | 支持相似历史召回 |
| 关系图谱 | Neo4j | 客户、账户、设备、商户、事件和风险信号 | 构建证据链和调查网络 |
| 业务持久化 | SQLite | 分析结果、趋势报告、复核动作 | 支持 Web 页面查询和回看 |
| 本地文件 | JSON、日志、截图、实验结果 | 演示报告和论文材料 | 支持可复现和可审计 |

## 3.4 系统闭环

Sentinel Edge 的关键不是单次模型问答，而是完整业务闭环。前置规则减少不必要的大模型调用，向量暂存保留低风险上下文，图谱构建提供证据链，多维风险评分给出统一风险尺度，趋势预测生成业务可读报告，人工复核动作又能为后续优化提供反馈。这样的设计更接近银行真实风控工作台，而不是孤立的文本分类器。
