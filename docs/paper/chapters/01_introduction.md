# 1 引言

随着移动银行、线上贷款和数字支付业务快速发展，银行零售风控面对的风险形态正在从单点异常转向跨账户、跨设备、跨商户和跨时间窗口的组合型风险。典型例子包括：诈骗资金通过多个新开户账户分散转入，再流向虚拟币平台；客户在异地新设备上进行异常转账；贷款申请前短期刷流水并伪造经营资料；多个交易对手和申请人存在同设备登录记录。这些风险往往不是单条规则能够完整识别的，需要结合事件文本、历史上下文、关系网络和合规信号进行综合研判。

传统金融风控系统通常以规则和阈值为核心，能够对黑名单账户、大额交易、异常备注等显性风险进行快速拦截。但在真实业务中，风险主体会通过拆分金额、变更账户、借用设备、包装流水等方式规避单点规则，导致人工分析员需要在交易系统、账户系统、设备系统、投诉系统和贷款系统之间反复查询。大语言模型为金融事件理解、证据总结和趋势报告生成提供了新的技术路径，但金融数据具有强隐私和强合规属性，若将客户交易、账户、设备和贷款资料上传到云端推理服务，会增加数据泄露、外部链路审计和弱网不可用等风险。

端侧 AI 为上述问题提供了更合适的落地方式。AMD 锐龙 AI MAX+ 平台具备 CPU、GPU、NPU 异构计算能力和统一内存架构，能够在本地工作站中同时承载大模型推理、向量检索、图数据库、业务 API 和前端展示等任务[1][2]。在本文实现中，显卡侧通过 llama.cpp 运行 Q6_K_M 量化后的 Qwen3.6-35B-A3B，承担风险解释和报告生成；NPU 侧通过 vLLM 部署 BGE M3 Embedding 与 BGE Reranker v2-m3，承担事件向量化、相似召回和重排；CPU 负责 Agent 编排、规则过滤、OpenAI 兼容接口调用和数据库访问；统一内存则有助于缓解多模型、多服务并行时的内存与显存压力。

本文提出 Sentinel Edge 银行零售反欺诈与反洗钱风险多智能体预警系统。系统围绕金融风控中的“事件输入 -> 本地推理 -> 工具调用 -> 图谱展示 -> 趋势报告 -> 人工复核”构建完整闭环。与单纯问答式应用不同，Sentinel Edge 将黑名单过滤、向量暂存、历史回捞、关系图谱、多维评分和复核动作纳入同一工作流，使大模型输出具备更清晰的业务依据和可复核路径。

本文主要贡献如下：

1. 提出面向银行零售反欺诈与反洗钱的端侧多智能体风控架构，实现本地模型推理、规则过滤、向量召回、关系图谱和人工复核的协同。
2. 设计低风险事件暂存与高风险事件回捞机制，使未命中高危规则的普通事件能够成为后续组合风险识别的历史上下文。
3. 设计多维风险评分方法，从客户身份、交易行为、交易对手、金额频次、设备地域、历史上下文和合规信号等维度生成可解释风险分数。
4. 基于 FastAPI、Vue3、Redis、Milvus、Neo4j 和 SQLite 实现全栈风控工作台，并围绕 AMD 锐龙 AI MAX+ 平台给出 CPU/GPU/NPU/统一内存协同使用方案[5][6][7][8]。
