# 6 AMD 锐龙 AI MAX+ 平台适配与异构资源利用

## 6.1 平台特点

AMD 锐龙 AI MAX+ 平台面向本地 AI 推理、科学计算和端侧应用部署，具备 CPU、GPU、NPU 异构架构和统一内存能力[1][2]。在 Sentinel Edge 场景中，银行金融事件文本、黑名单、图谱、向量索引和日志都在本地处理，对本地算力、内存容量和多服务并行能力有较高要求。

系统利用该平台的方式如下：CPU 负责 FastAPI 服务、智能体调度、规则过滤、OpenAI 兼容接口调用和数据库访问；集成 Radeon GPU 通过 llama.cpp 承载 Q6_K_M 量化后的 Qwen3.6-35B-A3B 大模型推理，用于风险解释和报告生成；Ryzen AI NPU 负责 BGE M3 Embedding 与 BGE Reranker v2-m3 推理，用于事件向量化、相似历史召回和召回结果重排；统一内存支持大模型、向量检索、图数据库和 Web 服务并行运行，降低传统独立显存瓶颈。具体硬件任务分工如表 5 所示。

## 6.2 硬件任务分工

**表 5 AMD 锐龙 AI MAX+ 平台硬件任务分工**

| 硬件资源 | 系统任务 | 设计理由 |
|---|---|---|
| CPU | API 服务、Agent 编排、规则过滤、OpenAI 兼容接口调用、数据库访问 | 控制流复杂，适合通用业务逻辑与多工具调度 |
| GPU | llama.cpp 大模型推理、风险解释、报告生成 | 显卡并行能力强，适合承载量化 LLM 的生成式推理 |
| NPU | BGE M3 Embedding、BGE Reranker v2-m3、向量化与重排 | 低功耗，适合高频文本表征与召回排序任务 |
| 统一内存 | 多模型、多数据库、多服务并行 | 缓解显存和内存数据搬运压力 |
| SSD | 日志、向量索引、图谱和报告持久化 | 支持本地审计和快速恢复 |

## 6.3 本地推理部署

系统核心推理默认在本地 AMD 平台执行，不上传客户隐私数据。大模型侧使用 llama.cpp 在显卡上运行 Q6_K_M 量化后的 Qwen3.6-35B-A3B，并通过 OpenAI 兼容接口对外提供 `chat/completions` 风格调用，使 CrewAI Agent、风险评估、意图分析和趋势预测能够以统一 API 访问本地模型。Embedding 与 Rerank 侧使用 vLLM 部署 BGE M3 与 BGE Reranker v2-m3，并将推理任务放在 NPU 上执行，用于 Milvus 暂存写入前的事件向量化、历史事件召回和候选结果精排。CPU 负责任务编排、规则判断、接口转发、数据库访问和日志记录，使模型推理任务与 Redis、Milvus、Neo4j、SQLite 和前端接口保持稳定协同。本地推理组件配置如表 6 所示。

**表 6 本地推理组件配置**

| 组件 | 模型或工具 | 部署硬件 | 量化方式 | 备注 |
|---|---|---|---|---|
| LLM | Qwen3.6-35B-A3B + llama.cpp | GPU | Q6_K_M | 风险解释、意图分析、趋势报告生成，通过 OpenAI 兼容接口调用 |
| Embedding | BGE M3 + vLLM | NPU | 本地推理配置 | 事件向量化、Milvus 暂存写入和相似历史召回 |
| Rerank | BGE Reranker v2-m3 + vLLM | NPU | 本地推理配置 | 对 Milvus 召回候选进行二次排序和噪声过滤 |
| Agent 调度 | CrewAI Flow + FastAPI | CPU | 不适用 | 编排智能体工作流，调用本地 OpenAI 兼容接口和工具服务 |
