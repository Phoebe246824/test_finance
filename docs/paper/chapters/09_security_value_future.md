# 9 隐私安全、应用价值与未来工作

## 9.1 隐私安全设计

Sentinel Edge 以本地部署为默认前提，客户交易事件、黑名单、向量索引、关系图谱、趋势报告和运行日志均保存在本机或企业内网。核心模型推理在本地 AMD 平台完成，其中显卡侧运行量化大模型，NPU 侧运行 Embedding 与 Rerank 模型，CPU 侧负责任务编排和 OpenAI 兼容接口调用，不向外部云端模型上传客户隐私数据。Demo 数据使用 P101、P102 等脱敏编号，避免出现真实姓名、身份证号、银行卡号和手机号。

系统在工程上保留了可扩展的安全设计：一是对日志和报告进行脱敏，避免敏感字段直接暴露；二是保留人工复核动作，便于审计风控决策过程；三是后续可接入登录鉴权、角色权限、操作审计、数据库加密和字段级脱敏；四是支持在银行内网中部署 Redis、Milvus、Neo4j 和 SQLite，减少外部依赖。

## 9.2 行业应用价值

系统的行业价值主要体现在以下方面：

1. **提升研判效率**：分析员可以在一个工作台中查看风险等级、命中证据、图谱关系和趋势报告，减少跨系统查询。
2. **增强组合风险发现能力**：低风险暂存和高风险回捞机制能够发现单点规则难以识别的历史关联。
3. **增强解释性**：多维风险评分、图谱证据链和趋势报告共同解释风险来源。
4. **适合内网落地**：端侧部署保护金融数据隐私，适合银行内网、弱网和离线复核场景。
5. **具备扩展性**：系统可扩展到信用卡盗刷、商户套现、保险理赔、贷后预警和对公账户风险监测。

## 9.3 落地路径

Sentinel Edge 可以按阶段落地：

1. 第一阶段：作为风控辅助研判工具，由分析员手动输入事件并查看图谱和报告。
2. 第二阶段：接入交易监控系统，对高风险事件实时预警。
3. 第三阶段：接入贷款、投诉、设备指纹、商户画像等更多业务系统。
4. 第四阶段：引入人工复核反馈，持续优化评分权重、提示词和召回过滤策略。
5. 第五阶段：与银行工单系统、冻结流程和审计系统对接，形成生产闭环。

## 9.4 未来工作

未来研究将围绕多源数据接入、生产级安全机制和端侧智能优化三个方向进一步展开。首先，系统可扩展贷款材料 OCR、凭证图像识别和合同关键要素抽取等多模态能力，使风险研判从结构化交易事件延伸到非结构化业务材料。其次，在工程落地层面，需要进一步完善角色权限控制、操作审计、本地数据加密和字段级脱敏机制，以满足金融生产环境对安全性、可追溯性和合规性的要求。此外，可继续优化 NPU 侧 Embedding 与 Rerank 的批处理、缓存和并发策略，在保证召回效果的同时降低持续监控场景下的计算开销与功耗。最后，系统还可面向批量事件分析和实时流式事件接入进行扩展，并引入基于人工复核反馈的持续优化机制，动态调整误报过滤策略和风险评分权重，从而提升模型在真实业务场景中的稳定性与适应性。
