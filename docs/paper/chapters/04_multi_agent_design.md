# 4 多智能体工作流与模型设计

## 4.1 多智能体任务拆分

金融风控任务具有步骤多、工具多、结果需复核的特点，因此本文采用 CrewAI Flow 对多个智能体和本地工具进行编排。当前系统中由 CrewAI Agent 承担的任务包括事件标准化、事件分类、风险评估、意图分析和趋势预测；黑名单过滤、图谱构建、历史回捞和业务持久化由 Redis、Graphiti/Neo4j、Milvus、SQLite 等本地工具服务完成。各智能体的输入、输出和主要职责如表 3 所示。每个任务都有明确输入、输出和可记录的中间结果，便于调试、复核和后续优化。

**表 3 多智能体职责划分**

| 智能体 | 输入 | 输出 | 主要职责 |
|---|---|---|---|
| 事件标准化智能体 | 原始事件文本 | 标准化事件对象 | 提取数据来源、标题、原文和事件时间 |
| 事件分类智能体 | 标准化事件文本 | 事件类型、关键实体、摘要 | 判断事件类型并抽取后续构图所需实体 |
| 风险评估智能体 | 事件、规则命中、图谱和检索上下文 | 风险分数、等级、维度分、解释 | 完成首次风险评分和高风险回捞后的二次评分 |
| 意图分析智能体 | 事件描述、风险等级、检索上下文 | 意图分析结果 | 分析事件背后的交易意图、动机和潜在影响 |
| 趋势预测智能体 | 意图分析结果、事件上下文 | 趋势报告、处置建议 | 预测风险演化路径并生成业务可读建议 |

## 4.2 本地模型能力

系统使用本地 LLM 完成金融事件理解、风险解释和趋势报告生成。为了避免云端推理带来的隐私风险，核心事件文本、客户编号、账户编号和风险线索均在本地 AMD 平台处理。当前实现中，Qwen3.6-35B-A3B 采用 Q6_K_M 量化并通过 llama.cpp 在显卡侧运行，对外暴露 OpenAI 兼容接口，供事件分类、风险评估、意图分析和趋势预测智能体调用。Embedding 模型使用 BGE M3，将事件文本转化为向量，支持 Milvus 相似历史召回；Rerank 模型使用 BGE Reranker v2-m3，对召回结果进行二次排序，过滤语义相似但业务无关的噪声。Embedding 与 Rerank 均通过 vLLM 部署在 NPU 侧推理，适合高频、低功耗的文本表征和排序任务。

检索增强生成方法能够让模型输出结合外部知识或上下文，提高事实依据和可更新性[4]。本文将该思想用于本地金融事件上下文召回：系统不直接把低风险事件丢弃，而是将其写入本地向量暂存池；当后续出现高风险事件时，再召回相似历史事件作为模型研判和图谱补全的上下文。

## 4.3 工具调用设计

系统为智能体提供以下本地工具：

1. 黑名单查询工具：查询 Redis 中的人员、关键词和高危事件样本。
2. 向量暂存工具：将低风险事件写入 Milvus，并对高风险事件执行相似召回。
3. 关系图谱工具：将事件实体和关系写入 Neo4j，并查询事件子图或人物子图。
4. 业务持久化工具：将分析结果、维度分、趋势报告和复核动作写入 SQLite。
5. 报告导出工具：导出 JSON 分析报告，方便论文、PPT 和演示视频复用。
6. 前端交互工具：支持图谱节点扩展、边详情查看和人工复核动作提交。

## 4.4 可复核中间结果

为满足金融风控的解释性要求，系统保留以下中间结果：

1. 黑名单是否命中、命中类别、命中对象。
2. 事件类型和分类依据。
3. 多维风险分数和最终风险等级。
4. 是否执行二次风险评估。
5. 历史回捞事件数量和过滤结果。
6. 图谱节点、边和属性。
7. 趋势预测报告和处置建议。

这些中间结果使系统输出不再是单一结论，而是可追溯、可解释、可复核的业务分析链路。
