# 2 行业背景与问题定义

## 2.1 业务场景

本文选择银行零售风控作为垂直行业应用场景，重点面向反欺诈、反洗钱和贷前风险识别三类任务。银行零售业务直接面对大量个人客户、小微商户和线上渠道，风险事件通常具有金额分散、主体众多、链路隐蔽和时效性强等特征。与单一交易异常不同，真实业务中的风险往往由多个弱信号叠加形成，例如“新设备登录、异地城市、向涉诈账户转账、交易备注包含虚拟币保证金”等组合特征，或者“经营贷申请前近 7 日流水异常放大、多个交易对手共享设备、纳税凭证时间不一致”等跨资料、跨主体异常。基于上述特征，系统主要覆盖电信诈骗转账拦截、反洗钱分拆交易识别、虚拟币资金归集识别、贷前欺诈识别、设备与地域异常识别以及历史相似事件复核等典型场景：一方面，通过涉诈账户、投诉账户、高危商户、虚拟币平台和异常交易备注等线索识别资金风险链路；另一方面，通过登录设备、常驻地域、交易对手、贷款材料和暂存事件之间的关联关系，发现传统单点规则难以捕捉的组合型风险。

## 2.2 目标用户

系统目标用户包括银行反欺诈分析员、反洗钱调查员、贷前风控专员、网点运营人员和合规复核人员。这些用户并不只需要一个风险等级，还需要知道风险由哪些证据支撑、命中了什么黑名单、相关主体之间有什么关系、历史上是否出现过类似事件，以及后续应该冻结、复核、放行还是转人工调查。

## 2.3 业务痛点

当前银行零售风控存在以下痛点：

1. **线索分散**：客户、账户、交易、设备、商户、投诉和贷款资料分布在不同系统中，人工查询成本高。
2. **组合风险识别不足**：传统规则更擅长识别单点异常，对多个弱信号叠加形成的风险链路识别能力有限。
3. **解释与复核压力大**：风控结果需要可解释、可追溯，不能只给出黑盒分数。
4. **历史上下文利用不足**：很多低风险事件被直接放行或丢弃，后续出现高风险事件时难以形成完整证据链。
5. **云端推理不适合敏感数据**：客户交易、账户、设备和贷款资料具有高敏感性，上传外部模型服务会带来隐私与合规风险。

## 2.4 端侧部署必要性

银行风控场景天然适合端侧 AI 部署。首先，端侧部署能够让金融数据不出机、不出企业内网，降低隐私泄露风险。其次，本地模型和本地数据库可以在弱网或离线环境中运行，适合银行内网、分支机构和现场复核场景。再次，端侧部署能够减少外部 API 调用链路，使日志、模型、图谱、向量索引和分析报告都处在可审计范围内。最后，AMD 锐龙 AI MAX+ 平台提供 CPU、GPU、NPU 与统一内存能力，为本地多模型并发和多服务协同提供了硬件基础[1][2]。
