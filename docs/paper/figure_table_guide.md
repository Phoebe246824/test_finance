## 图 1 Sentinel Edge 系统总体架构图

建议画成从上到下的分层架构图。

```text
用户 / 风控分析员
        |
Vue3 前端工作台
风险分析 | 事件库 | 事件详情 | 人物图谱 | 黑名单 | 总览
        |
FastAPI 后端 API
        |
多智能体工作流
标准化 Agent -> 分类 Agent -> 风险评估 Agent -> 意图分析 Agent -> 趋势预测 Agent
本地工具服务：Redis 黑名单过滤 / Milvus 暂存与回捞 / Neo4j 图谱构建 / SQLite 持久化
        |
本地工具与数据层
Redis | Milvus | Neo4j | SQLite | 本地日志/JSON 报告
        |
本地模型层
Qwen3.6-35B-A3B | BGE M3 | BGE Reranker v2-m3 | OpenAI 兼容接口
        |
AMD 锐龙 AI MAX+ 平台
CPU 编排与接口调用 | Radeon GPU 跑 llama.cpp 量化 LLM | Ryzen AI NPU 跑 BGE 向量与重排 | 统一内存
```

图的重点：让评委一眼看到“这是端到端系统”，不是单一模型 Demo。

## 图 2 端到端金融事件分析流程图

建议画成横向流程图。

```text
事件输入
  -> 事件标准化
  -> 黑名单过滤
  -> 是否命中高危？
       否 -> 低风险展示 -> Milvus 暂存 -> 结束
       是 -> 事件分类 -> 图谱构建 -> 多维风险评分
             -> 是否高风险？
                  否 -> 趋势报告 -> 前端展示 -> 人工复核
                  是 -> 历史回捞 -> 图谱补全 -> 二次风险评估
                        -> 趋势报告 -> 前端展示 -> 人工复核
```

图的重点：突出“低风险暂存”和“高风险回捞”这两个创新点。

## 图 3 金融事件关系图谱数据模型

建议画成实体关系图。

中心节点：

```text

```

周围节点：

```text
Customer / Account / Merchant / Device / RiskSignal
```

边示例：

```text
Customer / Account / Merchant -[TransfersFunds]-> Account / Merchant / Customer
Customer / RiskEvent -[UsesDevice]-> Device
RiskEvent / Customer / Account / Merchant / Device -[TriggersSignal]-> RiskSignal
RiskEvent / Customer / Merchant -[MatchesPattern]-> RiskSignal 或 RiskEvent
```

图的重点：说明图谱不是装饰，而是由 `graphiti_workflow.py` 中真实 schema 约束的风险证据链。

## 图 5 低风险暂存与高风险回捞流程图

建议画成两个时间阶段。

```text
T1：低风险事件
未命中高危规则 -> 显示低风险 -> 生成向量 -> 写入 Milvus 暂存池
```

图的重点：说明低风险事件为什么有价值。

## 表 1 传统云端大模型方案与端侧 AI 风控方案对比

建议内容：

| 对比项 | 云端大模型方案 | 端侧 AI 风控方案 |
|---|---|---|
| 数据流向 | 敏感事件需上传外部服务 | 数据保留在本机或银行内网 |
| 响应延迟 | 受网络和服务排队影响 | 本地推理，延迟更稳定 |
| 弱网能力 | 依赖公网或专线 | 可在内网、弱网或离线环境运行 |
| 审计可控性 | 外部链路较长，审计复杂 | 日志、模型、图谱均可本地审计 |
| 合规风险 | 需要额外评估数据出境和第三方处理 | 更符合敏感金融数据本地处理要求 |
