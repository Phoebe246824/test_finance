行业问题定义 银行零售风控

银行风控真正难的是“组合风险”与“隐私约束”

单条规则可以拦截显性风险，但反洗钱、跑分收款、账户盗用往往由多条低风险线索在时间上拼接而成。

01

数据分散

账户、流水、设备、客户资料、投诉线索分散在不同系统，人工串联耗时长。

02

组合风险漏检

多笔历史低风险 + 当前单笔异常，传统阈值和关键词规则容易割裂上下文。

03

敏感数据不能上云

客户身份、银行卡号、交易流水与设备指纹都要求内网留存、最小暴露。

目标用户：反欺诈分析员 / AML 调查员 / 贷前风控专员 03 / 13
端侧必要性 把人留在闭环里

把“事件 → 历史串联 → 定级 → 调查摘要”自动化

系统不是替代监管判断，而是让分析员拿到结构化证据和可追溯上下文，只把最终处置留给人。

隐私合规

推理、暂存、黑名单、图谱和日志默认在本机/内网完成。

弱网可用

网点、审计、专网场景不依赖公有云可用性。

低延迟处置

高风险交易需要即时解释、冻结建议与人工复核入口。

端侧闭环价值
在银行内网工作站上完成从事件接入、历史关联、风险解释到复核建议的闭环，减少敏感数据外流面，同时保留人工最终判断。
输入

交易、客户、设备、投诉等风险事件统一标准化。

研判

本地模型结合黑名单、向量回捞和图谱上下文完成风险分析。

复核

输出证据点、风险维度和处置建议，由风控人员确认。

定位：分析辅助 / 线索发现 / 人工复核，不替代最终监管判定 04 / 13

核心创新 面向组合型金融风险

四个设计让系统不只“判单条文本”

暂存 - 回捞机制

低风险线索不丢弃

未命中事件进入行为基线；高风险事件触发同客户、同账户、语义相关历史回捞。

多维风险评分

风险结果可解释

身份、交易行为、对手方、金额速度、设备地理、历史上下文、合规信号共同加权。

时序知识图谱

碎片线索织成关系网

Graphiti + Neo4j 记录人、账户、设备、事件、因果和参与关系，支持追溯。

二次研判闭环

先评估，再补图，再复评

高风险事件汇入历史上下文后重新检索和评分，输出证据点与处置建议。

创新侧重点：低风险不丢弃，高风险有上下文，结论可解释 06 / 13

隐私与安全 端侧部署的金融边界

本地部署是隐私底座，脱敏与复核是工程兜底

金融风控面对客户身份、账户流水和调查线索，系统设计必须默认减少数据外流面，并让处置责任保留在人。

本地部署护隐私

核心数据留在银行内网

推理、黑名单、暂存、图谱、检索和日志围绕端侧工作站部署，客户数据不依赖公有云传输。

脱敏 + 最小权限

Demo 用 P101 / P102 编号表达客户

展示链路用脱敏编号替代真实身份字段；接口、日志和复核入口只暴露完成任务所需的信息。

合规 + 人工复核

系统只做分析辅助和线索发现

风险等级、证据点和处置建议进入复核流程，最终冻结、上报或放行由授权人员确认。

审计友好
每次风险结论关联到触发规则、历史事件、图谱关系和复核动作，便于事后追溯。
安全口径：客户数据本地化、展示字段脱敏化、处置结论人工确认 11 / 13
