Sentinel Edge 端侧金融风控多智能体预警系统

面向银行零售反欺诈、反洗钱与贷前风控的本地化 AI 智能体实践
端侧 AI
金融风控
多智能体

关键问题与应用背景

  • 银行零售风险从单点违规转向跨账户、跨设备、跨商户、跨时间窗口的组合型欺诈。
  • 传统规则系统可拦截显性命中，但对分拆交易、跑分归集、虚拟币出入金、贷款包装流水等复杂链路识别不足。
  • 云端大模型具备文本理解与报告生成能力，但客户身份、账户、交易和设备数据上传外部云存在合规、审计和弱网风险。
  • 风控人员需要可解释证据链，而不是单一黑盒分数；系统必须支持人工复核和本地留痕。

作品目标

构建一个部署在 AMD 锐龙 AI MAX+ 平台的银行内网风控助手，在本地完成事件理解、黑名单过滤、向量召回、图谱构建、多维评分、趋势报告与人工复核闭环，实现“数据不出机、分析可追溯、风险可解释”。

系统架构与端到端流程

前端工作台
Vue3：总览、风险分析、事件库、事件详情、人物图谱、黑名单、系统状态
后端服务
FastAPI：事件分析、图谱查询、黑名单维护、人工复核、系统健康检查
智能体层
事件标准化、事件分类、风险评估、意图分析、趋势预测
工具层
Redis 黑名单、Milvus 向量暂存与回捞、Neo4j 图谱、SQLite 业务结果
硬件层
CPU 编排与数据库访问，GPU 承载 LLM/Embedding/Rerank，NPU 轻量预筛，统一内存支撑多服务并行
1输入金融事件文本，抽取客户、账户、商户、设备、金额和时间。
2Redis 执行人员、关键词、高危样本三路过滤，区分 PASS / STASH。
3低风险事件写入 Milvus 暂存池，保留后续组合风险上下文。
4中高风险事件进入 LLM 研判、Neo4j 构图和多维风险评分。
5高风险触发历史回捞，补全图谱证据链并生成趋势预测报告。

创新性关键技术

创新 01

低风险暂存 + 高风险回捞

未命中高危规则的事件不丢弃，而是经内容指纹去重后写入 Milvus；当后续出现高风险事件时，按主体、关键词和语义相似度召回历史线索，使“碎片化低危事件”转化为组合风险证据。

创新 02

图谱增强的可解释评分

以 Customer、Account、Merchant、Device、RiskEvent、RiskSignal 建模，结合 TransfersFunds、UsesDevice、TriggersSignal、MatchesPattern 等关系，输出 7 维风险分数与可复核证据链。

创新 03

端侧多智能体闭环

将事件标准化、分类、风险评估、意图分析、趋势预测拆成可审计智能体；核心数据、图谱、向量索引和报告留在本地，适配 AMD CPU/GPU/NPU/统一内存协同运行。

国内外同类方法对比

方法类别 代表形态 设计方法与主要参数 成本效益 竞争力评价
传统规则引擎 银行现有反欺诈/AML 阈值规则 人工维护黑白名单、金额阈值、频次阈值；可解释但组合关系弱 部署成本低，维护成本随规则膨胀上升 适合显性拦截，难覆盖新型团伙链路
云端大模型风控 外部 API 事件分析与报告生成 文本理解强，依赖公网/专线；数据需出域，审计链路复杂 按量计费，峰值调用成本不可控 通用能力强，但金融隐私与弱网场景受限
图数据库调查平台 Neo4j/知识图谱反欺诈分析 关系查询强，通常依赖人工建模与离线分析；缺少事件级 LLM 报告 适合调查团队，前期建模成本较高 证据链强，实时智能研判不足
Sentinel Edge 端侧 AI 多智能体风控工作台 Redis + Milvus + Neo4j + SQLite；7 维评分；PASS/STASH；历史回捞；图谱补全 一次本地部署，多场景复用；减少云调用与数据外发风险 兼顾隐私、解释性、弱网可用和工程闭环

对比测试与实验结果

10/10 功能正确性 正常交易、涉诈账户、AML、贷款欺诈、设备异常、跑分归集等 Demo case 均按预期完成。
100% 风险识别效果 风险等级一致率、高风险召回率、黑名单命中准确率在样例集上均达到 100%。
93.5% 图谱证据链 客户、账户、商户、设备、风险信号实体抽取完整率 93.5%，报告可用率 90.0%。
+20% 消融增益 仅 LLM 风险等级一致率 80.0%；完整系统提升至 100%，证明黑名单、回捞和图谱有效。
